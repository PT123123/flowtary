# Slint 双进程模型与内存占用

> 记录时间：2026-11-21，版本 1.3.4（Slint 渲染器架构）。
> 结论：`flowtary` + `flowtary-slint` 两个进程是设计结果；常驻内存比 GDI 时代更低，UI 进程活跃时总量略高但在可接受范围，暂不做优化。

## 1. 进程模型

| 进程 | 职责 | 生命周期 |
|---|---|---|
| `flowtary.exe` | 热键、搜索管线、索引、自学习、托盘、设置窗调度 | 开机常驻 |
| `flowtary-slint.exe` | 仅 UI：Slint 界面、亚克力背板窗口 | 第一次唤起时启动，之后常驻到应用退出 |

两者通过共享内存 + 命名消息通信（见 `src/slint_bridge.h` 与 `src/slint_ui/main.cpp`）：

- UI 崩溃不会拖垮搜索与热键，重建渲染器即可恢复界面。
- 渲染器不参与索引/搜索，唤醒路径上只做渲染和输入。
- 渲染器内部有两个窗口：主窗（逐像素透明，画阴影/高光/内容）和磨砂背板（DWM 亚克力，按面板矩形裁剪）。

## 2. 实测数据

测量时尚未唤起过 UI，渲染器未启动，只有大脑进程：

| 进程 | 私有工作集 | 私有提交 | 总工作集 |
|---|---|---|---|
| `flowtary.exe` | 5.0 MB | 6.2 MB | 39.4 MB |

- 任务管理器「内存」列显示的是**私有工作集**，约 5 MB。
- 总工作集里约 34 MB 是系统 DLL 的共享页，可被系统回收，不应当作应用独占开销。
- 老 GDI 版「一共十几 MB」的口径与私有工作集接近；大脑本体因为把界面搬走，反而更轻。

渲染器未启动时测不到真实值。按 Slint 软件渲染 + `slint_cpp.dll`（约 28 MB，代码页可回收）估算：私有工作集约 15–25 MB、总工作集 40–60 MB。

## 3. 是否比 GDI 差

| 场景 | 结论 |
|---|---|
| 不唤起（只有大脑） | 比 GDI 更好：约 5 MB 私有 |
| 全天挂着 UI 进程 | 约 20–30 MB 私有，比 GDI 的十几 MB 略高，同类启动器中仍属偏低 |

多出来的部分换来的是动画、亚克力模糊、自绘列表与主题系统。当前决定：保持常驻，不做额外优化。

## 4. 备选方案与取舍（暂不采用）

- **A. 隐藏后延时退出渲染器**（如 60 秒无交互退出）：内存可降回 5 MB 级，代价是冷唤起多 300–600 ms，热键响应变肉。
- **B. 保持常驻**：即时唤出，内存约 20–30 MB 私有。当前选择。
- **C. 合并回单进程**：少一次 IPC，但失去崩溃隔离，改造量大、风险高，不划算。
- **D. 压缩渲染器内存**（帧缓冲、字体/图标缓存）：收益只有几 MB，优先级低。

## 5. 复测方法

```powershell
Get-Process | Where-Object { $_.ProcessName -like '*flowtary*' } |
  Select-Object ProcessName, Id,
    @{n='WS_MB';      e={[math]::Round($_.WorkingSet64/1MB,1)}},
    @{n='Private_MB'; e={[math]::Round($_.PrivateMemorySize64/1MB,1)}}

# 任务管理器口径（私有工作集）
Get-Counter '\Process(flowtary-1.3.4)\Working Set - Private'
```

对照时注意区分三个口径：私有工作集（任务管理器显示）、私有提交、总工作集（含共享 DLL）。
